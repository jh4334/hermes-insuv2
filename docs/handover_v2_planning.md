# 모두의 인수인계 V2 — 기획 문서

> V1(기존 레포)은 **인계자 중심** 단일 트랙으로 계속 발전.
> V2(이 레포)는 **인계자 · 인수자 투트랙(토글)** + **자동 분류 엔진**이 핵심.
> 이 문서는 V1 개발 중 나눈 논의를 V2 관점으로 정리한 것.

---

## 1. 한 줄 정의

작년/올해의 공문(기안문서)을 카드로 뽑아 **업무 > 세부업무 > 단계 흐름**으로 구조화하고,
**떠나는 사람(인계자)** 은 깔끔한 인수인계서를 남기고 **받는 사람(인수자)** 은 맥락 없이도 업무를 파악·계획하게 한다.

## 2. 두 페르소나 (V2의 핵심 차별점)

| | 인계자 (넘기는 사람) | 인수자 (받는 사람) |
|---|---|---|
| 시점 | 올해 말, 자리 떠나기 전 | 내년 초, 자리 새로 맡음 |
| 업로드 | 내가 올해 기안한 문서 | 전임자가 작년에 기안한 문서 |
| 강점/약점 | 지식 O, 정리 도구 필요 | 문서만 O, 맥락 X |
| 목표 | 구조화 + 평가·환류 → 인수인계서 | 파악 + 올해 계획 수립 |
| 핵심 기능 | 구조도 편집, 평가·환류, 후임 지정 | 자동 분류 제안, 작년→올해 이동, 계획 생성 |

**둘은 별개 앱이 아니라 하나의 산출물(구조도=인수인계서)의 양 끝.** 인계자가 만들고 인수자가 받는다.
V2는 시작 시 **가벼운 토글**("내 업무 정리해 넘기기" / "받은·작년 자료 파악하기")로 문구·기본화면·기본 연도만 다르게 하고, **데이터 모델·엔진은 하나로 공유.**

## 3. 공통 핵심 흐름 — "일단 다 쏟고, 구조도에서 정리"

V1은 업로드할 때 세부업무명을 강제 입력한다. V2는 그 강제를 없앤다.

1. **업로드**: 올해(또는 작년) 내 이름으로 기안한 모든 문서를 우르르 → 전부 **카드**로 추출 (그룹명 강제 X)
2. **자동 분류 제안**: 엔진이 카드마다 단계 + 세부업무 후보를 제안, 확신 낮은 건 **미분류 더미**로
3. **구조도에서 정리**: 드래그로 세부업무를 만들고 → 세부업무를 업무로 묶고 → 카드를 단계에 배치
4. **산출**: (인계자) 인수인계서 DOCX / (인수자) 올해 계획·캘린더

## 4. 자동 분류 엔진 (V2의 심장)

완전 자동은 불가능. **층마다 난이도가 다르므로 층별 전략**을 쓴다.

| 층 | 난이도 | 전략 |
|---|---|---|
| **단계** (계획/심의·협의/품의/결과보고) | 쉬움 | 제목 키워드 규칙 (계획/보고/품의/위원회→심의). *V1에 이미 구현* |
| **세부업무** (통일, 안전교육) | 중간 | 제목 키워드 클러스터링으로 **묶음 제안** → 사람이 확인/병합 |
| **업무** (계기교육) | 불가능 | 자동화 X. 사람이 세부업무를 업무 버킷에 **한 번씩** 배정 (드래그) |

핵심 메커니즘:
- **확신 기반 라우팅**: 확신 높은 카드는 자동 배치, 낮은 카드만 미분류 인박스로 → 대부분 자동, 애매한 것만 수동
- **오답 학습(로컬 규칙 메모리)** ⭐: 사람이 "통일교육주간" 카드를 `계기교육/통일`로 옮기면 → `키워드 → 그룹` 규칙을 기억 → 다음 유사 제목 자동 배치. **학교 공문은 매년 반복**되므로 쓸수록 자동화율이 오른다. (ML 아님, 키워드→그룹 매핑 테이블이 자라는 구조 → 오프라인 가능)
- **무더기 검토 화면**: 우르르 넣으면 "이렇게 나눴어요"(그룹별 건수) → 일괄 확인/병합/이름수정
- **LLM 분류 (V2 온라인 모드)**: 온라인 허용 시 제목→업무/세부업무/단계 분류 정확도 대폭 상승. V1은 오프라인이라 규칙+학습만.

## 5. 계층 모델 (V2에서 정식화)

```
업무 (계기교육)            ← 여러 담당업무 중 하나, 복수 존재
└─ 세부업무 (통일)          ← 구조도 1장 = 여기, 계획→품의→결과보고 흐름
   └─ 사업 (통일교육주간)    ← (V2 신규) 세부업무 내 묶음. 제목에서 자동 추출 가능
      └─ 카드(공문)          ← 개별 기안문서, 단계 태그
```

- **V1**: `업무 > 세부업무` 2층 (그것도 구조도 전용 매핑, group_name 미변경).
- **V2**: 위 계층을 **정식 필드**로 승격. `사업` 층 추가 여부는 파일럿 피드백으로 결정.

## 6. 구조도 고도화 (V2)

V1은 세부업무별 단선 흐름(계획→품의→결과보고 + 미분류). V2에서 환경영향평가 포스터 수준으로:
- **책임 주체 레인**(담당/위원회/승인기관) 추가 — 스윔레인 2축
- **회귀(보완) 루프** — 반려 시 되돌림 화살표
- **정보 전달 화살표** — 3종 구분(절차순서/정보전달/보완회귀)
- **법정 위원회 메타데이터** — 위원회명·개최일·법정 근거·기한 경고·주기성(학기/월례)

## 7. 인수자 트랙 고유 기능 (V2)

- **작년 → 올해 이동**: 작년 공문을 올해 날짜로 자동 시프트 → 올해 실행 캘린더/계획 생성 (앱의 최초 비전)
- **맥락 보강**: 인계자가 남긴 평가·환류/후임 노트가 있으면 함께 표시, 없으면 자동 분류로 자력 재구성
- **인수인계서 수신**: 인계자가 만든 구조도/DOCX를 그대로 받아 열람

## 8. 데이터·아키텍처 메모

- V1: 완전 로컬(localStorage), 오프라인, 원본 PDF 미저장. → V2도 이 프라이버시 원칙 유지 권장
- V2 추가 고려: **온라인 옵션**(LLM 분류)은 명시적 동의 + 제목/메타만 전송(원문 최소화)
- **인계자↔인수자 전달**: 백업 파일(JSON)로 넘기거나, V2에서 공유 링크/계정 고려
- 후임별 분할 내보내기: V1에서 업무 영역별로 대체했으나, V2에서 `후임 담당자` 필드 부활 시 재검토

## 9. V1이 이미 해결해 둔 것 (V2가 물려받을 토대)

- 단계 축: `계획 → 심의·협의(위원회) → 품의 → 결과보고` + 위원회 키워드 자동분류 + 법정 위원회 시드 목록
- 업무 구조도 뷰: 세부업무별 스윔레인 + 자동 점검(결과보고 미등록/계획 몰림/품의 건너뜀) + 미분류 인박스 + 드래그 재배치
- `업무 > 세부업무` 그룹핑 UI (구조도 전용 매핑)
- DOCX 인수인계서: 지형도 + 연간 흐름 + 평가·환류(잘된 점/개선할 점) + 기안문 목록
- 업무 영역별 분할 내보내기(ZIP)
- 평가·환류 용어 통일, 로컬 백업/가져오기

## 10. 열린 질문 / 리스크

- 세부업무 자동 클러스터링 정확도 — 제목이 불규칙하면 과분할 위험 → 검토 화면 필수
- `사업` 층을 넣을지(3층 그룹) vs 카드 태그로 둘지 — 파일럿에서 확인
- 온라인 LLM 도입 시 개인정보 정책(공문에 실명·학생정보) — 전송 최소화·마스킹 필요
- 투트랙 토글이 오히려 혼란 줄 수 있음 → 온보딩에서 명확한 1문장 안내
