# Hermes Insu 개발방향 10개 및 검토 반영 로드맵

## 0. 최종 제품 문장

> 전년도 공문을 올해 업무 실행판으로 바꾸고, 교사가 보완할 누락·과밀·담당 미정 업무를 먼저 보여주는 로컬 업무 준비 도구.

`hermes-insu`는 인수인계 문서를 새로 쓰게 하는 앱이 아니다. 본체는 공문 기반 업무 흐름 시각화와 올해 업무계획 자동 생성이며, 인수인계는 업무 카드에 붙는 선택형 포스트잇 참고 메모로만 둔다.

## 1. 점검 방식

초안 10개 방향을 다음 3개 관점으로 병렬 점검했다.

1. 실제 교사/현장 사용자 관점
2. 업무개선 연구대회 심사위원 관점
3. 기술 아키텍처/범위 통제 관점

공통 결론은 다음과 같다.

- 가장 중요한 것은 `PDF 파서`가 아니라 `올해 업무 실행판`이다.
- 캘린더는 알림/시각화 표면이고, 앱의 지속 가치는 업무 카드·근거·보완 패널에 있다.
- 인수인계는 절대 본체가 되면 안 된다. 선택형 메모/칩 수준이 적절하다.
- 연구대회 효과 수치는 실제 파일럿 전까지 만들지 않는다.
- Windows EXE는 최종 배포에는 필요하지만 핵심 UX가 안정된 뒤 붙인다.

## 2. 최종 개발방향 10개

### 1. 추출 후보 미리보기 표

PDF 또는 붙여넣은 공문 목록에서 날짜, 제목, 문서번호, 전년도 담당자/부서, 참고자료 위치를 추출하고, 사용자가 업무계획 생성 전 표에서 수정한다.

**핵심 가치**
- 자동 추출 오류를 교사가 바로 보완할 수 있음.
- 완전 자동이 아니라 `교사 직접 점검` 구조라 신뢰성이 높음.

**주의**
- 원문 PDF 저장소를 만들지 않는다.
- 스캔 PDF/OCR 설치 안내를 최종 사용자에게 요구하지 않는다.

### 2. 올해 업무 실행판 생성기

전년도 공문 후보를 올해 기준 업무 카드로 변환한다. 날짜/제목 연도 롤오버, 단계 추론, 상태값, 근거 문서번호를 유지한다.

**기본 상태값**
- 보완 필요
- 수정 완료
- 확정
- 제외

**필수 필드**
- 업무명
- 올해 예정일
- 전년도 시행일
- 전년도 담당자/부서
- 문서번호 + 시행일
- 참고자료 위치
- 단계
- 상태

### 3. 업무 보완 패널

전체 목록보다 먼저 보완해야 할 업무를 보여준다.

**초기 보완 신호**
- 날짜 없음
- 담당자 없음
- 문서번호 없음
- 참고자료 위치 없음
- 낮은 추출 신뢰도
- 같은 주 업무 과밀
- 결과보고 누락 가능성

**권장 문구**
- `먼저 보완할 업무`
- `보완 이유`
- `누락 가능성 사전 보완`

### 4. 업무 카드 상세 패널

각 업무 카드 클릭 시 전년도 근거와 올해 실행 정보를 한눈에 보여준다.

**포함 정보**
- 작년 시행일
- 올해 예정일
- 전년도 담당자/부서
- 문서번호 + 시행일
- 원문을 찾을 참고자료 위치
- 단계
- 상태
- 선택형 포스트잇 참고 메모

### 5. 월별/주별 업무 흐름 시각화

연간/월간/주간 캘린더와 월별 업무 집중도를 보여준다. 캘린더는 제품 본체가 아니라 업무 흐름을 이해하게 하는 시각화 표면이다.

**초기 구현 원칙**
- 읽기 중심 캘린더부터 시작한다.
- 드래그앤드롭 일정 편집, Google Calendar 양방향 동기화는 후순위다.

### 6. 포스트잇형 참고 메모 UX

인수인계 문서 작성이 아니라 업무 카드별 짧은 참고 메모를 붙인다.

**권장 UX**
- 긴 textarea 중심 금지
- 칩/버튼 선택 중심
- 선택적 1줄 보충 메모
- 참고자료 위치 필드 강조

**예시 칩**
- 예산 보완 필요
- 관리자 결재 필요
- 외부기관 연락 필요
- 결과보고 필요
- 작년 민원/혼선 있음
- 자료 위치 보완 필요

### 7. 업무 흐름 묶음/단계 체인

관련 공문을 `계획 -> 품의 -> 운영 -> 결과보고` 같은 흐름으로 묶는다.

**초기 범위**
대표 유형만 규칙 기반 추천으로 시작한다.

- 체험학습
- 학교행사
- 예산·품의
- 정보공시
- 결과보고형 업무

### 8. 학교 제출용 내보내기 패키지

앱 안에서만 끝나지 않고 실제 학교 업무에 쓸 수 있는 산출물을 만든다.

**산출물 후보**
- 올해 업무계획표
- 월별 업무표
- 담당자별 업무표
- 보완 목록
- 업무 과밀·누락 목록
- 업무 흐름 묶음표
- 선택형 참고 메모 부록

**주의**
- 산출물을 `인수인계 문서`로만 부르지 않는다.
- `업무계획 및 참고 메모 내보내기`가 더 안전하다.

### 9. 연구대회 파일럿 증거 양식

실측값을 자동 생성하지 않고, 실제 파일럿 후 입력할 양식을 제공한다.

**양식 후보**
- 적용 전/후 업무분석 시간 기록표
- 추출 후 수동 보정 건수
- 누락 발견 건수
- 만족도 설문
- 재사용 의향
- 개인정보 보호 점검표
- 연구보고서 문장 틀

**표현 원칙**
- `[입력 예정]`, `[ ]분`, `[ ]건` 형태 유지
- 절감률/만족도/파일럿 결과를 임의 생성하지 않음

### 10. Windows EXE 배포 파이프라인

핵심 UX가 안정된 뒤 GitHub Actions 기반 Windows ZIP 배포본을 만든다.

**최종 사용자 안내**

```text
압축 풀기 → 모두의인수인계.exe 더블클릭
```

**주의**
- 최종 사용자에게 Python, pip, 터미널, OCR/Tesseract 설치를 안내하지 않는다.
- EXE는 포장 단계이며, 핵심 업무 흐름이 먼저다.

## 4. 다음 3개 Iteration 제안

### Iteration 1. 추출 후보 미리보기 표 + 올해 업무 실행판 계약 고정

**목표**
공문 후보가 어떻게 미리보기에서 수정되어 업무 카드가 되는지 데이터 계약을 확정한다.

**범위**
- `ExtractionCandidate` 도입
- 누락/불확실 필드 metadata status
- 사용자가 수정한 값이 `DocumentSeed`에 반영
- invalid date 거부
- raw PDF 경로/원문 저장 금지 테스트
- board 카드 기본 상태값 도입

**완료 기준**
- PDF 없이도 샘플/붙여넣기 데이터로 미리보기 표 -> 업무 실행판 흐름이 보인다.
- 추출 오류 수정값이 업무 카드에 반영된다.

### Iteration 2. 업무 보완 패널 + 업무 카드 상세 패널

**목표**
교사가 “먼저 뭘 보완해야 하는지” 알 수 있게 만든다.

**범위**
- 먼저 보완할 업무 큐
- 날짜/담당자/문서번호/참고자료 위치 누락 플래그
- 같은 주 업무 과밀 표시
- 업무 카드 상세 패널
- 후임자 참고 메모는 optional로 유지

**완료 기준**
- 대시보드 첫 화면에서 보완 우선순위가 보인다.
- 업무 카드 하나를 열면 작년 근거와 올해 해야 할 일이 보인다.

### Iteration 3. 캘린더/월별 흐름 + 내보내기 기초

**목표**
연구대회 시연과 실제 학교 사용을 위해 시각화와 산출물 뼈대를 만든다.

**범위**
- 연간/월간 업무 흐름 시각화
- 월별 업무 집중도
- 전체 업무계획표 CSV/HTML export 기초
- 보완 목록 export
- 연구대회 측정 양식 초안 문서화

**완료 기준**
- `전년도 공문 -> 올해 업무계획표/캘린더/보완목록` 시연이 가능하다.
- 허위 파일럿 수치 없이 측정 양식만 제공한다.

- K-에듀파인/NEIS/공문함 자동 수집
- watch folder 자동 감시
- OCR/Tesseract 설치 안내 또는 OCR 내장
- 실제 개인정보/실제 학교 문서 샘플 커밋
- Google Calendar 양방향 동기화
- 자동 성과 수치 생성
- 가짜 절감시간/가짜 만족도
- 로그인/권한/서버 배포
- 모바일 앱화
- 복잡한 drag/drop 일정 편집

- 사용자 지시 전 Windows 빌드 산출물 생성

## 6. 표현 원칙

- 자동화·성과를 단정하지 않고 교사 점검/수정 가능성을 함께 표시한다.
- 원문 파일을 장기 보관하거나 외부 서버로 보내는 듯한 표현을 피한다.
- OCR·동기화·파일 감시처럼 설치/권한 부담이 큰 기능은 현재 범위 밖으로 설명한다.
- 검증되지 않은 절감률, 파일럿 성과, 누락 방지 보장 표현을 쓰지 않는다.
- 인수인계 산출물 작성을 강제하지 않고 참고 메모/업무 카드 보완으로 안내한다.
